\section{Executive Summary}

Cyber AI Agent is a layered cybersecurity analytics system for detecting and explaining malicious network traffic. It ingests CSV flow records, preprocesses them into reusable artifacts, applies three complementary AI models, and fuses their outputs into a final threat verdict with a human-readable explanation. The project satisfies the assignment requirement to use multiple Advanced AI techniques by combining NLP, transformer-based transfer learning, and generative anomaly detection in one reproducible pipeline.

The system is implemented as a set of notebooks for training and evaluation and a FastAPI backend for runtime inference. The notebooks produce the scaler, label mappings, feature names, clipped values, trained models, and metrics used by the backend. The final service exposes upload, prediction, reporting, dashboard, and debug routes, enabling both demonstration and experimentation.

\section{Problem Statement \& Motivation}

Network intrusion detection often suffers from class imbalance, noisy features, and limited interpretability. Traditional detectors can identify attacks, but they do not explain why a record was flagged or how different models agree with each other. This project addresses those issues by combining a tabular classifier, a transformer-based text classifier, and an autoencoder-based anomaly detector, then adding an explanation layer on top.

The motivation is practical: a security team needs a system that can inspect flow logs quickly, identify suspicious traffic, reduce false negatives on rare attacks, and produce concise explanations that support incident response. The selected domain is Telecommunications, which is one of the recommended domains in the assignment and is well matched to network flow analysis.

\section{Literature Review}

This project builds on three established ideas in modern AI systems. First, supervised tabular classifiers such as gradient-boosted decision trees remain strong baselines for structured traffic features because they handle heterogeneous feature scales and class imbalance effectively. Second, transformer-based models such as BERT have demonstrated strong transfer-learning performance in many classification tasks and can be adapted here by converting each flow record into a natural-language description. Third, autoencoders are widely used for anomaly detection because they learn a compact representation of normal behavior and assign high reconstruction error to unusual inputs.

Recent applied cybersecurity systems increasingly combine multiple model families rather than relying on a single detector. This project follows that direction by using model diversity as a strength: XGBoost captures tabular structure, BERT captures semantic descriptions, and the autoencoder detects unusual patterns that may not be well separated in the supervised labels. The LLM explanation layer further improves usability by translating technical detections into analyst-friendly summaries.

\section{Methodology}

\subsection{Overall Pipeline}

The methodology follows a five-stage pipeline.

\begin{enumerate}[leftmargin=1.2cm]
    \item \textbf{Data ingestion}: CSV flow records are parsed, validated, and enriched with IP metadata.
    \item \textbf{Preprocessing}: The selected 18 features are cleaned, standardized, clipped, and saved with the fitted scaler and feature metadata.
    \item \textbf{Model training}: XGBoost, BERT, and a denoising autoencoder are trained independently using the notebook workflow.
    \item \textbf{Fusion}: The model outputs are combined using a weighted decision layer to produce the final attack label.
    \item \textbf{Explanation}: The top detected threats are passed to an LLM explainer that returns structured JSON narratives.
\end{enumerate}

\subsection{Preprocessing Strategy}

The preprocessing notebook selects 18 core network-flow features, removes duplicates, fills missing values, handles infinite values, applies standard scaling, and clips extreme scaled values at the 99th percentile per feature. Persisting both the scaler and clip values is important because the autoencoder and ensemble notebooks must consume the same transformed feature distribution during inference.

\subsection{Model Design}

XGBoost is used as the primary structured-data classifier and is trained with class-balanced sample weights to reduce bias toward dominant classes. BERT receives text generated from the same flow features and classifies attack types from a semantic representation. The autoencoder is trained only on benign samples, which lets it learn a compact normal-behavior manifold and treat high reconstruction error as anomaly evidence.

\subsection{Fusion and Explanation}

The ensemble layer combines model confidences using weighted fusion and then applies a threshold to suppress low-confidence alarms. The backend then enriches detected threats with external context and generates human-readable explanations. In environments where API credentials are unavailable, the LLM explainer falls back to mock mode so the demo remains runnable.

The FastAPI application loads all model layers at startup and routes each request through the following sequence: ingestion, preprocessing, XGBoost, BERT, autoencoder, fusion, MCP enrichment, and LLM explanation. This keeps training and inference decoupled while preserving the same transformation logic across notebooks and runtime services.

\section{Discussion}

The main strength of the project is its diversity of model families. The tabular classifier captures structured flow patterns, the transformer uses semantic text representations, and the autoencoder provides an unsupervised safety net for unusual traffic. The ensemble improves robustness by preventing any one model from dominating the final decision.

The main limitation is environment sensitivity on Windows, especially for TensorFlow and transformer imports. Another practical limitation is that the LLM explanation layer depends on valid API credentials unless mock mode is used. Finally, report numbers should be regenerated after the final notebook run so the written analysis matches the saved metrics.

\section{Conclusion \& Future Work}

Cyber AI Agent demonstrates a complete Advanced Artificial Intelligence project that combines NLP, transformer-based learning, generative anomaly detection, prompt-driven explanation generation, and ensemble fusion. The system is practical for a live demo and is structured so that each notebook can be rerun independently.

Future work should include packaging the notebooks into a single reproducible pipeline, adding automated smoke tests for artifact loading, integrating a front-end dashboard for analysts, and calibrating the fusion layer on a held-out validation set. A larger curated dataset and additional class balancing strategies could further improve rare-attack detection.
